# 本地数据库版（feature/local-db）

从 `master`（Supabase 网络数据库版）分出的本地化分支：**SQLite 本地数据库 + 自研极简 Auth + REST API 层**，定位为**单机自托管**部署。

> **分支策略（2026-08 决定）**：本分支**永远独立，永不合并回 main**。
> 两条线各自演进、各自发布：main = 网络数据库版（Supabase），本分支 = 本地单机版。
> main 上的 Supabase 相关变更**不要**同步到本分支；本分支的本地化改动也**不要**合入 main。

## 运行方式

```bash
pnpm install
# 可选：配置 AI 模型（默认 deepseek-v4-flash）
# .env.local: DEEPSEEK_API_KEY=sk-xxx

pnpm dev          # 并行起 vite(5173) + Hono(3001)，/api 代理到 Hono
# 或
pnpm build && pnpm start   # 生产模式（单进程托管 dist/ + API，单机自托管）
```

- 开发访问 http://localhost:5173（前端 HMR），生产访问 http://localhost:3001

- 数据库文件：`data/lotion.db`（WAL 模式；可用 `LOTION_DB_PATH` 覆盖路径）
- 上传图片：`data/uploads/`（可用 `UPLOAD_DIR` 覆盖）
- **每次启动自动执行迁移**（`lib/local/migrations.ts` 内嵌 DDL + `_migrations` 记录表），无需手动跑 SQL

## 架构

```
浏览器（React SPA，Vite 构建）
   │  fetch /api/*（同源 cookie 鉴权）
   ▼
Hono（server/*，Node 进程）──直查──► lib/local/db.ts ──► SQLite (better-sqlite3)
   ├── requireAuth 中间件（会话 cookie → c.get("user")）
   ├── 16 个 REST 端点（server/routes/*）
   └── 静态资源 dist/ + public/ + SPA 回退
lib/db.ts：客户端数据访问入口（全部 fetch REST，函数签名不变）
Auth：scrypt 密码哈希 + sessions 表 + HttpOnly cookie（lib/local/auth.ts）
路由守卫：API 层 requireAuth 中间件 + 前端 MainLayout 会话守卫（见 D4 / D12）
编辑器：BlockNote 0.54（@blocknote/core + react，默认 UI + 自有 CSS），
        规范存储 BlockNote JSON（无损）；服务端 JSON↔Markdown 走 @blocknote/server-util（lib/content-server.ts）
Agent/19 工具/压缩链路：直接接收 SQLite 连接（无 Supabase 依赖）
```

## 与 Supabase 版的差异（技术要点）

- **RLS 移除**：安全边界在应用层——本地层所有查询显式带 `userId`；REST 路由统一走 `userFromRequest` 鉴权
- **UUID**：`gen_random_uuid()` → 应用层 `crypto.randomUUID()`（`lib/local/sqlite.ts` 的 `newId()`）
- **时间戳**：TIMESTAMPTZ → TEXT(ISO 8601)；`updatedAt` 由应用层显式更新（无 PG 触发器）
- **BOOLEAN**：INTEGER(0/1)，本地层读写时映射
- **幂等**：`chat_messages(userId, requestId)` 部分唯一索引语义不变，冲突码 `23505` → `SQLITE_CONSTRAINT_UNIQUE`
- **搜索**：`ilike` → SQLite `LIKE ... ESCAPE '\'`（ASCII 大小写不敏感）
- **公开预览**：新增 `GET /api/public/documents/[documentId]`（无鉴权，仅 isPublished）

## 框架迁移（D12，2026-09）

从 Next.js 15 App Router 迁到 **Vite 8 + React 19 SPA + Hono 4**，分支 `feature/vite-hono`。

**动机**：Next.js 的差异化能力（SSR/RSC、ISR、Server Actions、Vercel 部署）在本项目**几乎未被使用**——
全站 51 个客户端组件、SSR 数据点仅 2 处（根布局注入 user + (main) 守卫），而部署形态是单机自托管
（SQLite + 本地磁盘，根本上不了 Vercel serverless），`next start` 退化成普通 Node HTTP server。
同时 Next 的约束还带来摩擦：Edge runtime 加载不了 `better-sqlite3`（D4 删中间件的根因）、
`serverExternalPackages` 补丁、`tsconfig jsx: preserve` 导致 vitest 需要 oxc 覆盖。

**迁移映射**：

| Next.js | 迁移后 |
|---|---|
| `app/**/page.tsx` + 路由组 | `src/pages/*` + `src/router.tsx`（react-router 7） |
| `app/**/route.ts`（16 个） | `server/routes/*`（Hono，`createApp()` 可测试） |
| `(main)/layout.tsx` 服务端守卫 | `server/middleware.ts` 的 `requireAuth` + `src/shell/main-layout.tsx` 客户端守卫 |
| `middleware.ts`（已删，D4） | 回归为 Hono 中间件（跑在 Node，无 Edge 限制） |
| `next/navigation`（20 处） | `react-router` 的 `useNavigate` / `useParams` / `Navigate` / `Outlet` |
| `router.refresh()` | `useUser().refreshUser()`（重新拉 `/api/me`） |
| `next/link` | `react-router` 的 `<Link to>` |
| `next/image`（3 处） | 原生 `<img>`（图源是本地 `/api/uploads/`，无优化收益） |
| `next/font/google` | `@fontsource/*` 自托管（离线可用，无 CDN 依赖） |
| `next/dynamic`（4 处） | `React.lazy` + `Suspense` |
| `import "server-only"` | 移除（Node 下会抛错）→ `test/boundary.test.ts` 静态边界守卫 |
| `next build`（Turbopack） | `vite build`（579ms，编辑器/emoji/shiki 语言包按需分包） |

**关键约束**：`package.json` 必须是 `"type": "module"`——`@blocknote/server-util` 的 CJS 构建
在 tsx 下会崩（`te.default.extend is not a function`），ESM 加载正常。

**代价**：首屏不再有服务端注入的 user，改为客户端引导 `/api/me`（`UserProvider` 内置，主界面加载期显示 spinner）；
失去 SSR/SEO——但公开预览页原本就是客户端渲染，marketing 页为静态内容，实际影响可忽略。
