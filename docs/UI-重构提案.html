08落地顺序：三步，每步都能单独合并

三批改动互不阻塞。第一批只动 token、不改组件结构（可脚本化替换 + 视觉零变化，最安全）； 第二批动结构（行元素、焦点、空状态组件）；第三批动信息架构（AI 面板呈现模式）。

Batch 1 · 零风险

Token 层收口

不改变任何视觉，只把散落的值收回 @theme。

  • 字级 6 档 + 圆角 4 档 + hairline
  • z-index 四档（干掉 z-[99999]）
  • 删除 10 个死 token（chart / sidebar-* / night）
~190 处替换 · 半天 · 视觉零 diff
Batch 2 · 结构

组件层修正

把"能点但键盘摸不到"的元素换成真控件。

  • 文档行 → <button role="treeitem"> + 焦点环
  • 行高 32 / 缩进 22 / 固定尾部区
  • 抽出 <EmptyState> 与 <Skeleton> 预设
~6 个文件 · 1–2 天 · 需回归侧栏交互
Batch 3 · 大改

AI 面板呈现模式

把"列宽"升级为"模式"，消除隐式让步链。

  • docked / overlay / fullscreen 三态
  • ⌘J 循环三态，偏好持久化
  • 窄屏不再被迫切布局
app-shell + use-layout · 2–3 天 · 需单测

验收口径（可写进 PR 模板）： ① 全仓 text-[ / rounded-[ / 0.5px 的命中数各自 < 10（只允许进 token 定义处）； ② 侧边栏全程可用键盘操作（Tab 可达、⏎ 打开、→ 展开）； ③ pnpm build 后 CSS 体积不增（token 化通常还会变小）。
